# Site direction: start with the work

## The problem with the previous landing page

The page used the same composition four times:

- small uppercase label
- serif heading
- explanatory paragraph
- one or two rounded buttons
- 80–112px of vertical padding

That made distinct projects feel like interchangeable marketing sections. The workshop registration appeared in the
announcement bar, header, hero, and closing call to action. The result was both repetitive and sparse.

## Reference observations

The redesign borrows principles, not layouts, from a small set of relevant sites:

- [Recurse Center](https://www.recurse.com/) names the lived experience immediately, shows people doing the work, and
  treats self-directed practice as the product.
- [School for Poetic Computation](https://sfpc.study/) gets its visual texture from real programs, dates, and people
  instead of abstract benefit copy.
- [Long Now](https://longnow.org/) holds several different projects under one strong idea, then lets each project
  become its own editorial chapter.
- [Vercel Ship](https://vercel.com/ship/sf) puts the place, date, event identity, and action in the first useful view.
- [Apple Intelligence](https://www.apple.com/apple-intelligence/) keeps one disciplined type and spacing system while
  giving each product chapter a distinct visual behavior.

## The concept

**Start with the work in front of you.**

The site is an editorial field guide with three ways into the same idea:

1. **Workshop** — begin in a room with one real problem.
2. **The Tinker Pledge** — keep the tools in reach so practice can continue.
3. **Podcast** — hear what other people tried, questioned, kept, or refused.

The workshop is primary. The pledge is the mechanism for continued access. The podcast expands the conversation
without pretending to be launched before the recordings exist.

## Landing-page flow

### Opening

One umbrella proposition and a three-part index. No competing hero button and no decorative AI image.

### 01 / Workshop

A dark working-room chapter with:

- a plain definition of the workshop
- one real-person image
- the next public event and one registration action
- three short notes about what happens in the room
- a small, factual reference to the first New York session

### 02 / The pledge

A light, paper-like public statement with:

- the employer ask in one sentence
- the home-computer analogy
- a single guardrail for company data
- links to the one-page pledge, proposal generator, and practical guide

### 03 / Podcast

A dark production-note chapter with:

- a real editorial question instead of a launch slogan
- the host and format
- an honest release status
- the working question list
- Eva's direct email address

## Visual system

- One 80rem content grid across the homepage and destination pages.
- Geist Sans carries the main hierarchy; Geist Mono is reserved for numbers, status, dates, and small labels.
- No feature-card grids on the primary flow.
- Borders create rhythm and alignment; rounded shapes are mostly reserved for actions.
- Warm paper, a dark Golden Hour Workshop chapter, and a deeper aubergine Podcast chapter create clear route associations without changing the layout.
- Large type is used once per chapter, with smaller text kept to readable 40–65 character lines.
- Desktop sections use 80–144px of vertical space according to content density; mobile sections use 56–80px.

## Media plan

The current workshop photograph is credited stock and should be treated as a bridge asset. The next public session
should produce:

- one wide room photograph
- two close working shots (hands, laptop, notes, facilitator beside participant)
- a short ambient video loop without staged reactions
- one concise participant explanation of the problem they brought

Those assets should replace the stock image without changing the page structure.

## Rules for future additions

- A new section must have a different job, not another way to restate the thesis.
- Show an actual date, room, artifact, question, or person before adding abstract benefit copy.
- Do not add testimonials until real participants have approved them.
- Keep public workshop registration as the primary action.
- Keep private sessions visibly secondary and explain that paid work helps cover the public project.
- Do not turn “coming soon” into a fake waitlist, guest list, or release date.
